# ADR-002: Каноническая модель тегов и адресации

## Статус
Принято (Accepted)

## Контекст
Различные семейства PLC и протоколы имеют различные форматы адресации (`DB100.DBD4`, `%DB100.DBD4`, `DB100,REAL4`, `ns=2;s=Temperature`). Web-HMI и прикладной уровень SCADA не должны зависеть от специфики протоколов.

## Решение
Ввести уровень канонической модели тегов (`packages/tag-model`):
- Каждый тег идентифицируется уникальным символьным ID в рамках PLC (например, `boiler1.feed_pressure`).
- Конфигурация тега содержит метаданные: человекочитаемое имя, единицы измерения (`unit`), пределы (`minValue`, `maxValue`), тип данных (`dataType`), интервал опроса (`pollGroup`), флаг разрешения записи (`allowWrite`).
- Физический адрес нормализуется парсером драйвера (`DB`, `M`, `I`, `Q` с байтовым смещением и битом).

## Последствия
- Полная независимость UI и бизнес-логики от используемого протокола связи.
- Возможность валидации конфигурации на этапе запуска сервера через JSON-Schema / Zod.
