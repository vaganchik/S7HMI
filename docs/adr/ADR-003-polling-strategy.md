# ADR-003: Стратегия опроса и пакетная оптимизация PDU

## Статус
Принято (Accepted)

## Контекст
Высокая частота опроса сотен и тысяч тегов создает критическую нагрузку на коммуникационный процессор контроллера при поштучном чтении тегов.

## Решение
Реализовать механизм `Batch Planner` в `PollingEngine`:
1. Группировать теги по блокам данных и областям памяти.
2. Объединять близко расположенные смещения (GAP <= 16 байт) в сплошные интервалы чтения.
3. Формировать запросы Multi-Variable Read (до 20 переменных в одном пакете) в рамках согласованного PDU (240 байт для S7-300/1200, 960 байт для S7-1500).

## Последствия
- Снижение сетевых накладных расходов в 10–30 раз.
- Гарантия соблюдения жестких интервалов опроса (100–500 ms) при 1000+ тегах.
