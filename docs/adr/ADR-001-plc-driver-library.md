# ADR-001: Выбор библиотеки и подхода к реализации S7-драйвера

## Статус
Принято (Accepted)

## Контекст
Для сервера Web-HMI/SCADA требуется надежный драйвер связи с контроллерами Siemens S7-300, S7-1200 и S7-1500. Были исследованы:
1. `node-snap7` (C++ Addon через NAN, оборачивающий Snap7 C library).
2. `nodes7` (plcpeople - чистый JS, устаревший callback API).
3. `@st-one-io/nodes7` (чистый JS, современный, но лицензия GPL-3.0).
4. Разработка собственного модульного TypeScript драйвера `packages/plc-s7` с интерфейсом `IPlcDriver`.

## Решение
Разработать собственный модульный драйвер `S7ClassicDriver` на чистом TypeScript поверх стандартного `net.Socket` Node.js с реализацией протоколов RFC 1006 (TPKT), RFC 905 (COTP Class 0) и S7 Communication (Header 0x32).

## Последствия
- **Плюсы:**
  - 100% стабильность процесса Node.js без риска native segfaults.
  - Нулевые нативные зависимости (мгновенная сборка и запуск на Windows, Linux, Docker Alpine, ARM64).
  - Лицензионная чистота (MIT / Apache) без риска GPL-заражения коммерческого продукта.
  - Полная поддержка строгой типизации TypeScript.
  - Полный контроль над очередями, отменой запросов и таймаутами.
- **Минусы:**
  - Необходимость самостоятельной реализации и покрытия тестами кодеков S7comm PDU.
